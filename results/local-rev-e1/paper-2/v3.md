# Personalization Drives Most of the Polarization in Human–AI Recommendation Loops — But Retraining Cadence and Feature Specification Interact in Non-Obvious Ways: An Agent-Based Study

## Abstract

Recommender systems are canonical socio-technical systems: trained on human behavior, they shape the content humans see, and are then retrained on the behavior their own recommendations produced. A common hypothesis is that this closed loop of *retraining on self-generated engagement* drives opinion polarization and shrinking content diversity. We test this with a lightweight agent-based simulation (300 agents, scalar opinions, logistic-regression recommender) comparing random, static (train-once), adaptive (periodically retrained), and adaptive-with-diversity-injection conditions. With a well-specified recommender (features that can represent the ground-truth engagement rule), static and adaptive personalization roughly triple final opinion variance relative to random (0.070 vs. 0.023) and cut content diversity ~22%; the static-vs-adaptive gap (0.0699 vs. 0.0686) is small but statistically real (paired t(4)=6.43, p=0.003, Cohen's d=2.88 on n=5 matched seeds). A retrain-frequency sweep (1–40 rounds) changes variance by <2%, and — after fixing a degenerate comparison flagged in review (retrain-every-40 never actually fires mid-run in a 40-round simulation) — this null result survives even under concept drift when tested against a retraining schedule that genuinely fires mid-run (retrain-every-20; t(2)=−0.12, p=0.92). Diversity injection sharply reduces polarization once it crosses a discrete per-user threshold (2 of 5 slots). We also test recommender misspecification: with a fully linear feature set (missing the interaction term), static variance collapses to 0.004 while adaptive variance explodes to 0.289 (paired t(2)=−25.0, p=0.0016, d=−14.4), and the effect is non-monotonic across retrain frequencies. A new partial-misspecification sweep shows this is *not* a smooth transition: dropping only the distance feature (but keeping the raw opinion-item product) produces catastrophic, retraining-cadence-*insensitive* polarization (var ≈0.95, static ≈ adaptive), while dropping only the product term (keeping distance, which alone recovers the true rule) behaves like the well-specified case. So whether retraining cadence matters at all is not a function of "how misspecified" a recommender is in any scalar sense, but of *which* feature is missing.

## 1. Introduction

The socio-technical framing of AI recognizes that algorithmic systems and the humans who use them co-evolve: a model shapes user behavior, that behavior becomes training data, and the retrained model shapes behavior again (Cinus et al., 2022; survey by Wang et al., 2024). This human–AI feedback loop is widely cited as a driver of echo chambers, polarization, and declining collective content diversity.

Much of the existing simulation literature conflates two mechanisms: (1) *personalization* — recommending content similar to revealed preferences, which alone can induce confirmation-biased engagement even from a never-updated model; and (2) *retraining* — the recommender continuing to learn from engagement its own past recommendations produced. Prior work (Cinus et al., 2022) shows personalization increases echo chambers under network homophily; surveys (Wang et al., 2024) document individual-vs-collective diversity tension. None of these ask whether the recommender's own capacity to represent the engagement rule changes the answer, or which specific missing feature matters.

**Research question.** How much of the polarization attributed to "feedback loops" is due to (a) personalization existing at all, (b) retraining cadence, (c) diversity injection, and (d) the recommender's feature capacity — including *which* features are present, not just how many?

**Contributions.** (1) A small, reproducible agent-based simulation cleanly separating personalization from retraining cadence. (2) Paired-seed statistical tests (t-tests and Cohen's d, not just means ± std) for all matched-seed comparisons, honestly reporting small sample sizes (n=3–5). (3) A concept-drift condition, corrected in this revision to use a retraining schedule that actually fires mid-run. (4) A misspecified-recommender experiment, extended in this revision with a partial-misspecification sweep showing the retraining-cadence effect is tied to a *specific* missing feature, not to misspecification severity in general. (5) Open code and logs.

## 2. Related Work

**Feedback loops in recommenders.** Cinus et al. (2022, *arXiv:2112.00626*) show recommenders amplify echo chambers primarily when the network already has homophily; our setup has no network structure, isolating the content-recommendation channel. **Surveys.** Wang et al. (2024, *arXiv:2407.01630*) document individual-vs-collective diversity tension, which we measure via content-diversity entropy. **Simulation frameworks.** A 2025 framework (*arXiv:2510.14857*) models the retrain-on-own-logs loop but does not isolate cadence or recommender capacity; ours is complementary and narrower. **LLM-based social simulation.** LLM user-simulator work documents sycophancy artifacts (*arXiv:2505.13995*, *arXiv:2505.23840*); we did not pursue this empirically (no hosted-API access in this offline environment) and flag it as follow-up. None of this prior work asks whether the recommender's feature capacity — or *which specific feature* is missing — changes conclusions about retraining cadence; we keep the model minimal to isolate exactly that.

## 3. Method

**Population and content.** N = 300 agents hold a scalar opinion in [-1, 1], initialized from truncated Normal(0, 0.3). Each round, C = 500 candidate items are drawn uniformly from [-1, 1].

**Engagement model (ground truth).** Engagement probability is sigmoid(β₀ + β₁·(1 − |opinion − item position|)), β₀ = −1.0, β₁ = 4.0. On engagement, opinion moves 8% toward the item's position, plus noise (σ = 0.01/round).

**Recommender feature sets.** Logistic regression on: `full` = [opinion, item, product, |opinion − item|] (well-specified, can represent the ground-truth rule exactly); `no_dist` = [opinion, item, product] (missing the distance term); `no_product` = [opinion, item, |opinion − item|] (missing the product term, but retains the feature that alone recovers the true rule); `linear_only` = [opinion, item] (fully misspecified, cannot represent any nonlinear similarity).

**Conditions:** random, static (fit once after a 3-round cold start, frozen), adaptive (refit every `RETRAIN_EVERY` rounds on all accumulated logs), adaptive_diverse (adaptive + a fraction `DIVERSITY_EPS` of slots replaced with random candidates). 5 seeds for the main comparison, 3 seeds for ablations, T = 40 rounds, K = 5 recs/agent/round.

**Concept-drift condition.** The ground-truth similarity target shifts over time: engagement probability uses |opinion − (item + 0.01·round)|, so the "ideal" content position drifts by up to 0.4 over the 40-round run. **Correction from the previous revision:** we originally compared retrain-every-1 against retrain-every-40, but with T=40 rounds, `(round+1) % 40 == 0` fires only at the final round — that refit is never used to generate any recommendation, making "retrain-every-40" mechanically identical to "static" (confirmed: the raw per-seed variances were bit-for-bit identical). We now compare against retrain-every-20, which fires at round 19 and is actually used for rounds 20–39.

**Paired significance testing.** For all matched-seed comparisons we report paired t-tests and Cohen's d, since conditions share seeds/cold-start logs and n is small (3–5).

**Metrics.** Final opinion variance; Sarle's bimodality coefficient; fraction |opinion| > 0.6; content-diversity entropy of engaged-item histogram.

**Implementation.** Pure NumPy + scikit-learn; `simulate.py`/`ablation.py` reproduce the base results, `revision_experiments.py` adds the paired tests, corrected drift condition, misspecified recommender, retrain-frequency sweep under misspecification, and the new partial-misspecification sweep. Total wall-clock for all experiments: ~17 seconds on one CPU core.

## 4. Results

**Main comparison (mean ± std, 5 seeds, well-specified recommender):**

| Condition | Opinion Var. | Bimodality | Frac. Extreme | Content Diversity |
|---|---|---|---|---|
| random | 0.0233 ± 0.0015 | 0.178 ± 0.004 | 0.000 | 2.258 ± 0.001 |
| static | 0.0699 ± 0.0054 | 0.172 ± 0.004 | 0.025 | 1.751 ± 0.034 |
| adaptive | 0.0686 ± 0.0054 | 0.172 ± 0.005 | 0.023 | 1.748 ± 0.033 |
| adaptive_diverse | 0.0243 ± 0.0010 | 0.172 ± 0.003 | 0.000 | 1.897 ± 0.011 |

Personalization triples variance vs. random and cuts diversity ~22% (paired t(4)=17.5, p<0.001, d=7.84). The static-vs-adaptive gap is small but real (t(4)=6.43, p=0.003, d=2.88 for variance; t(4)=5.13, p=0.007, d=2.30 for diversity) — retraining has a small, consistent negative effect on polarization, but it is two orders of magnitude smaller than the personalization-vs-random effect, so retraining cadence remains a low-leverage lever *given a well-specified recommender*.

**Retrain-frequency ablation** (3 seeds, well-specified): variance ranges from 0.0684 to 0.0698 across `RETRAIN_EVERY` ∈ {1,...,40} — a ≤2% spread.

**Concept-drift experiment (corrected).** Under a slowly drifting content-preference target, static (0.0692±0.0055), adaptive-retrain-every-1 (0.0688±0.0058), and adaptive-retrain-every-20 (0.0688±0.0060) are statistically indistinguishable (paired t(2)=−0.12, p=0.92, d=−0.07 for retrain1-vs-retrain20). Unlike the previous revision's comparison, retrain-every-20 genuinely fires mid-run (round 19) and is used for half the simulation, so this null result is no longer an artifact of a retraining schedule that never activates. The mechanism holds: the adaptive recommender refits on *all* accumulated history rather than a recency-weighted window, so more frequent full-history refitting does not track a drifting target any better than infrequent refitting.

**Misspecified-recommender experiment (fully linear features).** With features [opinion, item] only, static variance is 0.0038±0.0026 — *below* the random baseline, because a linear-only model fit on a short cold-start log cannot recover the nonlinear rule and recommends near-randomly. Adaptive variance is 0.2895±0.0179 (paired t(2)=−25.0, p=0.0016, d=−14.4): repeated retraining on the model's own increasingly biased logs lets it bootstrap a much sharper decision boundary than any single fit could. A retrain-frequency sweep (3 seeds) shows this is non-monotonic: 0.065 at RETRAIN_EVERY=1, 0.32–0.33 at 2–10, and 0.004 at 40 (≈static) — n=3 per point, so we treat the qualitative non-monotonicity as suggestive rather than precisely located.

**Partial-misspecification sweep (new).** We tested two intermediate feature sets to probe whether the well-specified→misspecified transition is smooth:

| Feature set | Static var. | Adaptive var. |
|---|---|---|
| full (well-specified) | 0.0698 | 0.0686 |
| no_product (has distance) | 0.0646 | 0.0646 |
| no_dist (has product only) | 0.9530 | 0.9554 |
| linear_only (fully misspecified) | 0.0038 | 0.2895 |

The transition is not smooth or ordered by "amount" of missing information. Dropping only the product term (`no_product`) — which still retains the true rule's distance feature — behaves like the well-specified case, with static≈adaptive, as expected since this feature set can already represent the ground truth exactly. Dropping only the distance term (`no_dist`) — keeping the raw product, which is a poor proxy for |opinion−item| — produces catastrophic polarization (var≈0.95, near the theoretical ceiling for opinions in [-1,1]) that is essentially *insensitive* to retraining cadence (static≈adaptive), unlike the fully-linear case. Only the fully linear feature set shows the large, cadence-dependent, non-monotonic behavior reported above. This directly answers the round-2 review's question: the cadence-sensitive bootstrapping effect is not a generic property of "misspecification," it is contingent on the specific feature choice — removing the wrong single feature can produce a *worse*, cadence-*insensitive* failure mode than removing two features together.

**Diversity-injection ablation** (3 seeds): threshold-like — ε=0.0/0.1 (0 slots replaced of K=5) are identical (var 0.0686); ε=0.2 (1 slot) roughly halves variance to 0.0345; ε≥0.3 (2+ slots) drops to ≈0.022–0.024, matching random. This is an artifact of the small K=5 slate discretizing the intervention.

**Interpretation.** Retraining cadence is low-leverage only when the recommender already has a feature sufficient to recover the ground-truth rule from a short cold start. When it lacks the *right* feature, two qualitatively different failure modes appear: cadence-insensitive catastrophe (`no_dist`) and cadence-dominant non-monotonicity (`linear_only`). We cannot yet predict from feature-set structure alone which regime a given misspecification falls into — a limitation, not a resolved question.

## 5. Conclusion

Using a compact, reproducible agent-based simulation, we find that whether "retraining cadence" is a meaningful policy lever depends on recommender specification in a more complicated way than "well-specified vs. under-specified." With a well-specified recommender, personalization alone accounts for nearly all measured polarization and diversity loss relative to random recommendations; retraining cadence has a small but statistically real effect (two orders of magnitude smaller than personalization), and this null result survives both mild concept drift and a corrected, non-degenerate retraining schedule. With misspecified recommenders we see two distinct regimes: a fully linear feature set produces a large, non-monotonic, cadence-*dependent* polarization swing (adaptive ~75x static), while dropping only the distance feature (keeping a cruder product term) produces even worse, cadence-*independent* catastrophic polarization. Diversity injection remains a highly effective, threshold-sensitive lever (2 of 5 slots randomized restores near-baseline variance) across all regimes. For practitioners: if your recommender's features already capture the relevant similarity structure, retraining frequency is low-leverage and diversity injection should be prioritized; if it doesn't, the *specific* missing signal — not just the amount of missing capacity — determines whether cadence is worth tuning or the model is already saturated regardless of retraining. Limitations: paired tests rest on 3–5 seeds (effect sizes reported for calibration; proper confidence intervals need more seeds than our budget allowed); we tested one drift rate and four feature sets, not a continuous sweep; assimilation/noise-parameter sensitivity (round-1 review) remains untested. We flag a recency-weighted retraining variant, a continuous feature-ablation sweep, and the sycophancy-simulation extension as next steps.
