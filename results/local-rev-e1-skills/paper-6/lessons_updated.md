# Skills / lessons for writing better first drafts

- Before framing a result as a "finding," check whether it follows directly from the algebra/construction of your own method, or could be explained by an obvious confounding variable in your own setup (e.g., a discretization/functional-form choice, or a covariate like set size that differs between the two things you're comparing). If so, either (a) don't present it as a standalone empirical discovery, or (b) proactively run the cheap confound-controlled ablation in the first draft, not only after a reviewer asks. A recurring, expensive pattern: a headline "method A vs. method B" difference measured at matched nominal parameters (e.g., matched alpha) turns out to be substantially explained by the two methods landing at different set sizes/scales — always ask "matched on what?" and test the alternative matching before claiming the difference is intrinsic to the thing you want credit for. A related shape: if two things you're comparing are mathematically guaranteed to induce the same partition/ranking under your chosen operationalization (e.g., an "exact-match" clusterer makes your semantic-clustering method identical in mechanism to your simpler baseline), say so explicitly and up front — a near-tie you can prove is definitional is a weaker finding than an empirical surprise, and a paper that owns this in the method section (rather than letting a reviewer point it out) reads as more rigorous, not less ambitious.
- When presenting several interventions/conditions as points on one comparable spectrum or ranking, check that each is a like-for-like manipulation before writing the headline ranking. If one condition mechanically changes an axis the others don't (e.g., swapping an entire agent for a different agent class, rather than adding a policy layer on top of the same underlying agents), decompose it (e.g., report the per-agent/per-component breakdown) in the first draft, not after a reviewer asks — and be honest in the abstract, not just in a buried results paragraph, about how much of the headline pooled effect is compositional versus a genuine behavioral change.
- Every summary statistic in the abstract must be a number you can point to in the results body, not a loose paraphrase. Compute the actual range/ratio across conditions and either report the range or the correct aggregate — don't round a spread of effects (e.g., 2.5x–8.5x) into one punchy headline figure (e.g., "quadruples") that doesn't match any single reported value. This applies to plain counts and tallies too, not just ratios: if the abstract states a total number of sensitivity cells/conditions/checks, recompute it by literally adding up the sub-sweeps described in the method section before submitting — a paper was flagged for an abstract claiming "21 sensitivity cells" when the described sweeps only summed to 12, a discrepancy a reviewer catches by simple addition.
- Any p-value reported as a strict bound (e.g., "p < 1e-41") must actually satisfy that inequality against the number in your own artifact — don't derive the bound by truncating an exact value's mantissa to 1 (e.g., rounding 2.79e-41 down to "p<1e-41" is false; the correct bound is "p<1e-40" or, better, report "p≈2.8×10⁻⁴¹"). This is a distinct, mechanical check separate from ordinary arithmetic recomputation: for any exponent-style claim, verify the direction of the inequality, not just the order of magnitude. Reviewers who are already re-running your code will independently recompute exact p-values and catch every instance of this, and it reads as a systematic overstatement pattern (not a one-off typo) if it appears more than once — prefer "≈" notation over ad hoc "<" bounds unless you've explicitly checked each one.
- When a headline effect is a discontinuity/threshold/phase-transition claim, test it at finer resolution than your main sweep grid before submitting — a coarse grid cannot distinguish a true jump from a fast multi-step decline, and reviewers will ask for exactly this check.
- Avoid post-hoc, unjustified cutoffs used to classify results into categories (e.g., "a drop >0.03 counts as a narrow band"). Either use a threshold-free characterization (slope, derivative, AUC of the curve) or report a sensitivity analysis across a reasonable range of thresholds from the start, and be explicit about which conclusions are threshold-sensitive.
- When you run a series of ablations across revisions, check that you're not only ever varying one axis of the setup while leaving other obviously-relevant axes completely untested through every round. This applies at two levels: reviewers will flag an entire untested axis (e.g., only the human/behavioral-model side varied, never the base classifier/dataset), but once every axis has at least one ablation, they will then flag *insufficient diversity within* an axis you did technically cover — e.g., testing robustness to "network structure" with only a single random graph topology (one Erdős–Rényi draw) is treated as a narrower claim than it sounds, and a paper that found a genuinely different qualitative result under that one topology got asked whether the effect is specific to that topology's degree distribution or would generalize to others (e.g., scale-free, small-world). Budget first-draft effort toward covering a couple of structurally different instances per axis you claim to have stress-tested, not just one. When a reviewer's follow-up question can be answered by re-analyzing data you already collected (e.g., fitting a cross-condition regression over cells from a prior ablation) rather than running a new simulation, do the cheap re-analysis first — it's fast to produce, trivial for the reviewer to re-verify (no new artifact to rerun), and still counts as a substantive, responsive answer.
- If your central phenomenon has a known general mathematical explanation, explicitly connect it to that existing theory/prior work. Otherwise, reviewers will read framing like "phase transition" or "sharp threshold" as overclaiming novelty even when the empirical execution is rigorous — connect mechanism to prior theory before claiming surprise value.
- More rounds of technically excellent, honestly-reported ablations do not guarantee a monotonically increasing review score. Across several papers now, the rating has sat flat (or even dipped a point before recovering) for the final 2-4 rounds even though every concrete reviewer request was fixed each round: once the easy methodological critiques (missing significance tests, missing ablations, unverified thresholds, missing artifacts, seed-count mismatches, incorrect p-value bounds) are resolved, reviewers shift to scrutinizing the core contribution's novelty/significance, related-work depth, and whether the paper's own honesty is shrinking its contribution. One failure shape: a paper launches with two co-equal headline contributions, and rigorous stress-testing across rounds demotes one of them (sign-flips at low seed count turn out to be noise, or the effect is shown to be hyperparameter/topology-dependent) — leaving, by the final round, only one "robust, load-bearing" claim and one "illustrative, not calibrated" claim. A second shape (papers that explicitly disclaim novelty and frame themselves as "an evaluation harness, not a new algorithm"): the score stays capped regardless of added rigor, because the ceiling is set by contribution type. A third shape, seen when a toy/synthetic setup stands in for a real target domain: reviewers keep flagging the same "this is a proxy, not the real mechanism" gap every round even as every *other* requested fix lands cleanly — added rigor within the proxy domain (more seeds, richer variants, power analyses) demonstrably strengthens the proxy-domain claims but cannot, by construction, close the proxy-vs-real gap, so it stops moving the score once that's the dominant remaining critique. A fourth shape (a fully self-consistent simulation with essentially no correctness weaknesses left to find): the score can plateau one point below the ceiling for the paper's whole remaining lifetime simply because the sole recurring weakness — a single, coarse external calibration point — is real but structurally unfixable within the paper's scope (no access to more human-subject data), so reviewers keep naming it without it ever being resolvable in-paper. Where possible, figure out in the first draft which of your candidate claims is actually going to survive heavy stress-testing (run the cheap high-seed-count sensitivity checks *before* writing the abstract), and if your design is inherently a proxy for a domain you can't directly test (no internet, no production access, no real dataset), decide up front how you'll anchor it to that domain (see below) rather than spending three rounds proving the proxy is internally solid while the external-validity gap goes untouched.
- Related-work sections that give one-sentence characterizations of each cited paper (or stay in the 5-8 total citation range) get flagged as shallow, and this critique tends to recur across multiple review rounds unaddressed if not fixed early — engage substantively with at least the most central 2-3 citations (what they measured, what they didn't test, how your parameters relate to any quantity they report), and expand citation breadth to cover the wider space of related models/approaches, not just the one or two papers you calibrated against.
- Don't assert a novelty claim ("we are not aware of prior work that...") without substantiating it against the broader literature in the same section. An unsupported novelty assertion gets flagged as thin even in a late-round, otherwise well-defended paper — either cite enough related work to make the claim credible or soften it to a scoped statement about what you did test.
- If your method is a simulation/proxy standing in for a real-world system or domain, find at least one empirical anchor point from cited literature — or a real-world spot-check, even partial — to calibrate against, even approximately. Leaving the mapping from simulation parameter/regime to the real-world target entirely untested through every revision is a recurring, unresolved weakness reviewers keep raising across multiple papers in this series. This applies even inside a fully synthetic setting with no external data available: if a central mechanism (e.g., a regulatory detection trigger) assumes access to ground-truth information no real-world actor would have (e.g., the true market-clearing/Nash price), that gap gets flagged every single round until a first-draft proxy/realistic-information variant is tested. It also applies when a hard environment constraint (e.g., a sandboxed machine with no internet access) makes running the real-domain experiment literally impossible: in that case the cheapest available anchor is a *numeric* one — pull the actual reported effect sizes/AUROCs/gaps from the papers you're already citing as your target domain, and state explicitly in the text how your proxy's effect size compares in magnitude. A paper that never quotes "our synthetic gap is X, the real-domain literature reports Y" leaves reviewers to ask this as a question every round instead of getting an answer; citing published numbers costs nothing (no internet needed, just reading your own reference list closely) and it's usually a cheap addition since the rest of the writeup already exists. Note that even a well-executed single anchor (one interpolated number checked against one human-subject study) tends to get flagged as "coarse" every round it remains the *only* anchor — if a second, independent real-world number is available from a different cited study, add it, since reviewers evaluate anchor *count and diversity*, not just anchor presence.
- Ship deterministic, self-contained, fast-running code alongside every numeric claim in the paper, and double-check before each submission that every artifact/log file path named in the text actually exists in the submitted directory. Full exact reproducibility (a reviewer can rerun your script and match your numbers to the last reported digit) has been consistently rewarded across every review round of every paper in this series — reviewers explicitly rerun the full pipeline each round, so it's cheap to provide and materially increases reviewer trust, and any single missing or non-reproducing number stands out sharply against that reviewer's baseline expectation of exact fidelity. If seeds are derived from strings/tuples via hashing, never use a language's built-in general-purpose hash function for this unless you've confirmed it's stable across processes — e.g., Python's `hash()` on strings/tuples is randomized per-process by default (PYTHONHASHSEED), so code that looks deterministic (fixed base seed + `hash(params)`) can silently produce a different run every single execution despite the paper claiming exact reproducibility. Use a purpose-built stable hash (e.g., `hashlib.sha256` on an encoded string) for any seed-derivation step, and verify determinism by actually diffing outputs from two fresh-process reruns, not just by reading the code and assuming a fixed base seed is sufficient.
- Recompute every ratio/"roughly Nx" comparison stated in prose directly from the numbers you report elsewhere in the same paper before submitting, especially after a late revision changes an upstream number. Reviewers who are already verifying your code will also hand-check your arithmetic and tallies, and a stale or miscalculated figure is a concrete, easily-caught overclaim that undermines an otherwise rigor-focused paper. Also reconcile the same figure if it's quoted more than once (e.g., abstract vs. main text) against slightly different reference numbers — pick one comparison basis and use it consistently.
- Beyond arithmetic, check that prose *characterizations* of a result (e.g., "never significant," "no effect," "robust across conditions") match the actual number and p-value in your own results table, not just a plausible-sounding summary of it. A revision once described a table cell as "never significant, even reversing sign" when the same table's own paired-t p-value for that cell was p=0.005 (Bonferroni p=0.019) — i.e., a statistically significant reversal, and a materially more interesting finding than the prose claimed. Reviewers cross-check narrative sentences against your own tables just as readily as they check them against external facts, so add a pass before submission where you re-read every qualitative claim in the text next to the specific cell/row it's summarizing. When a later round's more targeted follow-up ablation contradicts or narrows a blanket claim made in an earlier round (e.g., "no detectable effect" becomes "a small, real effect at the single most extreme condition tested, absent everywhere else"), explicitly revise/retract the earlier sentence in the text rather than only appending a new caveat beside it — reviewers have explicitly praised this as "the kind of update a reviewer wants to see, not just added caveats," and it reads as stronger evidence of rigor than defending the original broader claim would.
- If a sweep or ablation turns up one anomalous/outlier cell or an unexpected sign flip relative to the rest of the grid, don't just flag it as unexplained and move on, and don't assume it's noise (or assume it's real) without checking — rerun that specific cell/slice at a matched, higher seed count before concluding either way. This is a recurring, two-sided pattern: a paper that ran most of its sensitivity grids at a lower seed count than its main sweep (e.g., 10-15 seeds vs. 30) got asked whether every "surprising" cell was sampling noise; when it reran, most flips did indeed turn out to be noise, but one flip reran as a genuine, statistically decisive reversal (p<0.0001) that changed the paper's qualitative story in that regime. The lesson is not "sign flips are always noise" — it's that any ablation run at reduced seed count relative to your main sweep is not yet a trustworthy claim in either direction, and matching seed counts across all sensitivity checks in the first draft avoids an entire extra review round spent just re-running at higher N. This applies with special force to whichever finding turns out to be your most novel/consequential one. In practice, reviewers may not always flag a lower-seed-count ablation explicitly (a paper can score well while its sensitivity sweeps run at 20 seeds/cell vs. a 30-seed main grid) — but treat the mismatch as latent risk rather than evidence the practice is safe, since whether it gets caught seems to depend on whether any specific cell result looks surprising enough to invite scrutiny.
- When you claim a small-sample effect is "seed-stable," "not noise," or "reliably significant," back it with a formal paired statistical test (paired t-test, Wilcoxon signed-rank) in the same draft you make the claim — don't rely on informal evidence and wait for a reviewer to ask for the formal version. If a reviewer (or you, anticipating one) notices the effect is only *sometimes* significant at your default sample size, the strongest response is an actual power analysis — sweep n across a few values, run multiple independent replicates at each, and report the fraction reaching significance at each n. This converts "seed-sensitive, might be fragile" into a concrete, defensible statement ("reliably significant, 5/5 replicates, at n≈1200; at our default n=300 it's real but not always significant, which is the expected behavior of a modest true effect at that sample size") — a materially stronger and more honest answer than either overselling the default-n result or shrugging at the inconsistency. When a test has a known small-sample floor, report that floor honestly alongside the more appropriate test rather than omitting the unfavorable result.
- If a diagnostic or mechanism check (e.g., a "why does this happen" measurement like a frozen/discarded-update fraction) is used in the text to explain a headline numeric result, make sure that diagnostic is computed on the *exact same run/grid* that produced the headline number, not a separate, smaller, or differently-parameterized sweep that merely overlaps in spirit. A reviewer will explicitly check whether the explanatory diagnostic and the effect it explains come from the same data, and quoting a mechanism percentage from a different experiment than the effect size it's meant to justify is flagged as a reproducibility/rigor gap even when both numbers are individually correct and reproducible.
- A plausible-sounding post-hoc mechanistic explanation for a surprising result (especially a counterintuitive one, like a noisier/weaker-information version of a mechanism outperforming the "ideal" version) should either be tested directly with an added diagnostic, or explicitly labeled as untested speculation in the same sentence — don't let confident prose about "why" a result happened stand in for evidence that the proposed mechanism is actually what's driving it. Reviewers will accept the effect size as established (if reproducible) while separately flagging the causal story behind it as unverified, so keep those two claims visibly distinct in the writing.
- When a paper reports many individual significance tests across a large sensitivity grid (e.g., 15-20+ per-cell p-values across several stress-test dimensions), address multiple-comparisons correction explicitly — either apply one, or state briefly why it's not needed (e.g., effect sizes are large/consistent enough that correction wouldn't change conclusions). Leaving a large multi-cell battery of p-values entirely unaddressed on this point gets flagged even in an otherwise well-regarded late-round paper.
- When a reviewer (or your own read of the results) calls an effect size "small," "modest," or "practically marginal," first check whether the estimate is an artifact of a narrow or arbitrary design choice you made when constructing the experiment (e.g., a hand-picked set of only 3-4 variants/conditions/perturbations meant to illustrate a mechanism, not to bound it) before accepting the "modest effect" framing as final. Testing a broader or richer version of that same choice — more variants, more diverse instances, a wider parameter range — can reveal your original number was a conservative lower bound rather than the true effect size, which is a substantially stronger rebuttal than defending or hedging the original modest number. Explicitly framing a follow-up experiment this way ("if this generalizes the wrong way, it hurts our story, so it's a real test, not padding") also helps the reviewer trust the result wasn't cherry-picked.
- If an ablation/robustness axis turns out to be structurally broken (e.g., a nuisance variable creates label imbalance so severe that a whole metric is undefined for some conditions no matter how you resample), attempt exactly one dedicated rescue in the round after it's first flagged — e.g., resample more draws, or sweep the one knob (training budget, sample size, hyperparameter) most likely to fix it. If that rescue attempt shows the imbalance is structural (moving the knob in one direction fixes one sub-condition while breaking an adjacent one, rather than fixing all of them at once), say so plainly and stop investing further rounds trying to rescue it — report it as an intrinsic limitation of the task/setup design instead of re-attempting fixes each round. Reviewers explicitly downgrade papers less for having one clearly-diagnosed-as-unfixable ablation than for spending multiple rounds re-poking at the same broken axis without ever concluding it's unfixable; by the third round of a still-broken ablation, reviewers themselves may suggest cutting it, which is a signal you should have reached that conclusion first. Better still: when designing the first draft, sanity-check whether any planned difficulty/nuisance axis scales so steeply that no single operating point can give every level of that axis balanced positive/negative labels — catching this before the first draft avoids the wasted rounds entirely.
- When a low-dimensional summary/predictor for a multi-parameter effect is proposed (e.g., "the ratio of two rates predicts where an effect flips sign better than either rate alone"), test it against the obvious alternative summaries (difference, product, each raw parameter alone) in the same round you propose it, not just the one you expect to win — reviewers will ask for exactly this comparison, and running it yourself first, including reporting where your favored summary still falls short (e.g., residual scale-dependence at fixed ratio), reads as more credible than presenting only the winning candidate.
